# Управление Kodme

Команды выполняются из папки с `compose.yml`.

## Запуск и остановка

```bash
podman-compose up -d        # запустить всё
podman-compose ps           # состояние сервисов
podman-compose down         # остановить и удалить контейнеры (volumes сохраняются)
podman-compose down -v      # ⚠️ то же + удалить volumes (потеря БД!)
```

## Получение и обновление образа Kodme

Образ публикуется в GitHub Container Registry (pull — без авторизации):

```bash
podman pull ghcr.io/bukreevlad/kodme:latest
podman-compose up -d --no-deps --force-recreate kodme kodme-media-worker
```

Запасной реестр — `registry.kodme.ru` (pull — без авторизации). Перетегируйте
образ под имя из `compose.yml`:

```bash
podman pull registry.kodme.ru/kodme:latest
podman tag registry.kodme.ru/kodme:latest ghcr.io/bukreevlad/kodme:latest
```

Резервный путь (реестры недоступны): `podman load -i kodme.tar.gz` →
`podman tag localhost/kodme:latest ghcr.io/bukreevlad/kodme:latest` → `podman-compose up -d`.
nginx перезапускать не нужно — backend адресуется по статическому IP.

## Статика веб-клиента

Образ Kodme содержит только сервер — статику веб-клиента nginx раздаёт
с хоста из каталога `./nginx/html/web-client` (он смонтирован в nginx).
Каталог заполняется из репозитория исходников клиента:

```bash
git clone <репозиторий-клиента> /tmp/kodme-web-client
cd /tmp/kodme-web-client && bun install && bun run build
mkdir -p nginx/html/web-client && cp -r /tmp/kodme-web-client/dist/* nginx/html/web-client/
podman-compose restart nginx
```

При обновлении клиента достаточно повторить `build` + копирование и
перезапустить nginx.

## Сервисы

```bash
podman-compose restart <service>    # перезапуск (nginx | kodme | kodme-media-worker | ...)
podman-compose logs <service>       # логи
podman-compose logs -f <service>    # логи в реальном времени
```

## Аппаратное ускорение (GPU) для медиа-воркера

Рендеринги видео (360/720/1080) транскодируются фоном. По умолчанию
транскодинг идёт на CPU (libx264) — работает везде, но медленнее. С GPU
(NVENC/VAAPI/QSV) воркер ускоряется в разы:

1. На хосте должен быть GPU с драйверами: NVIDIA — драйвер + `nvidia-container-toolkit`,
   Intel/AMD — `libva` и VA-драйверы (проверка на хосте: `vainfo` —
   H.264 encode/entrypoint в списке профилей).
2. В `compose.yml` сервиса `kodme-media-worker` раскомментируйте блок
   `devices: /dev/dri` + `group_add: video, render` и пересоздайте сервис:
   `podman-compose up -d --no-deps --force-recreate kodme-media-worker`.
3. Проверка — строка в логе воркера при старте: «аппаратное ускорение: ...»
   либо «не найдено — софт» (авто-детект молча откатывается на софт, если
   GPU нет или его H.264-энкодер не прошёл проверку).

Принудительно выключить GPU-путь: `media_processing.hardware_acceleration: "off"`
в `kodme/config.yaml`. Образ драйверов не содержит — они берутся с хоста.

## PostgreSQL

```bash
# консоль
podman exec -it postgres psql -U kodme -d kodme
# backup
podman exec postgres pg_dump -U kodme -Fc kodme > ./postgres/backup/backup-$(date +%Y%m%d).dump
# restore (-c очищает существующие объекты перед восстановлением)
podman exec -i postgres pg_restore -U kodme -d kodme -c < ./postgres/backup/backup-<дата>.dump
```

## Очистка

```bash
podman container prune -f   # остановленные контейнеры
podman image prune -f       # dangling-образы
podman system prune -f      # все неиспользуемые ресурсы
```
