# Пагинация

Списки (сообщения, диалоги, каналы, трансляции, контакты, сессии и т.п.)
загружаются **порциями** на основе id записей (UUIDv7). Общие правила
описаны в [websocket/README.md](../websocket/README.md).

## Параметры запроса

| Поле | Тип | Описание |
| --- | --- | --- |
| `direction` | `string` | `"next"` — более новые записи (вверх), `"prev"` — более старые (вниз). Если не указано — с начала списка (как `"next"`). |
| `cursor_id` | `UUIDv7 \| null` | Id записи, относительно которой грузится порция. |
| `offset` | `int` | Размер порции. |

## Механика

1. Первый запрос: `{ "direction": "next", "cursor_id": null, "offset": 35 }`.
   Сервер возвращает порцию от начала.
2. Каждый следующий запрос передаёт `cursor_id`:
   - для продолжения **вниз** (`prev`) — id **первой** (самой старой) записи
     полученной порции;
   - для продолжения **вверх** (`next`) — id **последней** (самой новой) записи
     полученной порции.
3. Когда ответ содержит порцию меньше запрошенной (либо пустой массив) — конец
   списка в данном направлении.

## Лимиты

| Метод | По умолчанию | Диапазон |
| --- | --- | --- |
| `[message]: get history`, `[message]: get data`-порции, большинство списков | `35` | 1–100 |
| `[channel]: get user conversations`, `[user]: get contacts`, `[channel]: get invites` | `100` | 1–100 |
| `[channel-profile]: *` | `100` (handler) | 1–300 |
| `[invite]: get invites`-порции (там, где применимо) | по описанию метода | 1–300 |

> Диапазон уточняйте в описании конкретного метода: сервер возвращает ошибку
> `INVALID_OFFSET`, если значение вне допустимого.

## Пример (история сообщений)

```json
{ "channel_id": "…", "direction": "next", "cursor_id": null, "offset": 35 }
```

```json
{ "channel_id": "…", "direction": "next", "cursor_id": "UUIDv7-последнего", "offset": 35 }
```
