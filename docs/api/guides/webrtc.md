# WebRTC / LiveKit: звонки, конференции, секретные чаты

Все медиа-сценарии платформы строятся на WebRTC:

- **Звонки** (`[call]`) — 1-1 и групповые звонки через LiveKit.
- **Конференции** (`[meet]`) — групповое медиа через LiveKit.
- **Секретные чаты** (`[secret-chat]`) — прямое P2P-соединение устройств:
  сообщения и файлы не проходят через сервер.
- **Секретные звонки** (`[secret-call]`) — прямые P2P-звонки с медиа между
  устройствами (шифрование DTLS-SRTP — стандарт WebRTC).

## ICE-серверы

Клиент получает ICE-серверы **один раз** из HTTP
`POST /api/v1/auth/check` → `server_data.web_rtc.ice_servers`:

```json
[ { "urls": ["stun:..."], "username": "...", "credential": "..." } ]
```

Серверы генерируются персонально (логин/пароль) и используются во всех
WebRTC-соединениях клиента.

## Звонки (LiveKit)

События — [calls.md](../websocket/client-to-server/calls.md). Медиа идёт через
LiveKit: участники получают **токен доступа к комнате звонка** и подключаются
к LiveKit-совместимому эндпоинту `wss://<host>/api/v1/meet` (тому же, что у
конференций), публикуя и подписывая треки.

```
Звонящий (A)                             Сервер                        Собеседник (B)
    │  [call]: start {user_id}             │                               │
    │─────────────────────────────────────►│  push [call]: incoming ─────►│
    │◄─ {call_id, token, is_merged} ───────│                               │
    │                                      │   [call]: accept {call_id}    │
    │                                      │◄──────────────────────────────│
    │                                      │── {call_id, token} ─────────►│
    │         подключение к комнате LiveKit по своим токенам (A и B)      │
    │◄────────────────────── медиа через LiveKit ────────────────────────►│
    │  [call]: leave {call_id}             │                               │
    │─────────────────────────────────────►│  (выход виден по событиям     │
    │                                      │   LiveKit-комнаты)            │
```

- Отказ/таймер/отмена — `[call]: decline` и `leave`; итоговое завершение
  приходит push `[call]: declined` (см. [calls.md](../websocket/server-to-client/calls.md)).
- **Групповые звонки**: `[call]: add participant` добавляет участника (ему —
  свой `[call]: incoming` и токен), а `[call]: start` к собеседнику с уже
  идущим звонком вливается в него (`is_merged: true`).
- Приватность: `privacy_calls` собеседника (`"all"` / `"contacts"`).

## Конференции (LiveKit)

События — [meets.md](../websocket/client-to-server/meets.md). Медиаобмен
происходит через LiveKit SDK, отдельное (второе) WebRTC-соединение.

1. `[meet]: create { name, about, is_public, is_chat }` → `{ meet_id }`.
2. `[meet]: open { meet_id }` — клиент подписывается на комнату `meet::<meet_id>`
   и получает объект Meet **+ `token`** (JWT для LiveKit). Остальным участникам
   комнаты — push `[meet]: user enter`.
3. Клиент подключается к LiveKit по `token` (комната LiveKit совпадает с `meet_id`),
   публикует/подписывает треки.
4. `[meet]: close { meet_id }` — отписка от комнаты и push `[meet]: user exit`
   остальным участникам.

Приглашение по ссылке: `[meet]: create invite` → объект [Invite](../objects/invite.md);
вход по приглашению — `[invite]: open`-механика (см. [invites.md](../websocket/client-to-server/invites.md)).

## Секретные чаты (P2P)

События — [secret-chats.md](../websocket/client-to-server/secret-chats.md).
Сервер участвует только в сигналинге и присутствии; контент (сообщения,
файлы) шифруется на устройствах и передаётся напрямую (WebRTC DataChannel).

```
Устройство A                             Сервер                        Устройство B
    │  [secret-chat]: invite {ключи}       │                               │
    │─────────────────────────────────────►│  push [secret-chat]: incoming │
    │◄─ {delivered: true} ─────────────────│──────────────────────────────►│
    │                                      │  [secret-chat]: accept {ключи}│
    │                                      │◄──────────────────────────────│
    │◄─ push [secret-chat]: accepted ──────│                               │
    │  [secret-chat]: signal (offer/answer/candidate)                      │
    │─────────────────────────────────────►│  push [secret-chat]: signal ─►│
    │        прямое P2P-соединение (DataChannel): сообщения и файлы        │
    │◄───────────────────────────────────────────────────────────────────►│
```

- Ключ соединения устройства вычисляют сами из ключей handshake; при
  переподключении согласование повторяется (`rekey`).
- Приглашение уходит **на все онлайн-устройства** собеседника (как звонок):
  каждое показывает экран приглашения, чат ведёт принявшее устройство
  (`accept`); отказ/снятие приглашения — `decline`.
- Доставка контента — только при совместном онлайне; онлайн-устройства
  собеседника узнаются подпиской на присутствие (presence).
- Чат привязан к паре устройств: на новом устройстве история пустая.

## Секретные звонки (P2P)

События — [secret-calls.md](../websocket/client-to-server/secret-calls.md).
Как и секретные чаты — прямое P2P-соединение устройств, но с медиа
(аудио/видео шифруются DTLS-SRTP — стандартным шифрованием WebRTC).
Секретные звонки независимы от секретных чатов: свой раздел `[secret-call]`
и свой идентификатор разговора.

1. Звонящий узнаёт онлайн-устройства собеседника (presence) и шлёт `offer`
   каждому из них — каждое показывает экран входящего звонка.
2. Принявшее устройство отвечает `answer`, устройства обмениваются
   `candidate` — медиа идёт напрямую (или через TURN — уже зашифрованным).
3. `hangup` — отказ/отмена/завершение; остальным устройствам звонящего можно
   разослать его после установления соединения.

Как и у секретных чатов, доставка сигнала — только при совместном онлайне
устройств.
