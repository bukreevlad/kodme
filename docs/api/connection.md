# WebSocket-соединение

Основной транспорт клиента — WebSocket-соединение с сервером.

- URL: `wss://kodme.ru/api/v1/wss/client`
- Авторизация: access-токен передаётся при установке соединения (websocket-протокол `Sec-WebSocket-Protocol` / заголовок `Authorization`), см. [authentication.md](./authentication.md).
- Если соединение не авторизовано — сервер закрывает его с кодом **1008** (`Authentication failed`).

> Помимо клиентского соединения есть **выделенное соединение бота**
> `wss://kodme.ru/api/v1/wss/bot?token=...&botId=...` — см.
> [bots-to-server](./websocket/bots-to-server/README.md).

После подключения сервер:

1. подписывает соединение на личные и канальные комнаты пользователя;
2. оповещает собеседников и контакты событием `[user]: online status`;
3. начинает доставлять push события (S2C).

## Формат кадров

### Клиент → сервер (C2S event)

```json
{
  "type": "event",
  "event": "[domain]: action",
  "data": { ... },
  "callbackId": "любая-строка"
}
```

- `callbackId` — опционален. Если передан, сервер ответит callback-кадром с тем же `callbackId`.

### Сервер → клиент: callback (ответ на C2S)

Успешный ответ:

```json
{
  "type": "callback",
  "callbackId": "любая-строка",
  "error": null,
  "data": {
    "data": { ... },
    "status": true,
    "timestamp": "2026-09-21T12:34:56.789Z"
  }
}
```

Ошибка (обработчик вернул ошибку):

```json
{
  "type": "callback",
  "callbackId": "любая-строка",
  "error": null,
  "data": {
    "status": false,
    "message": "EMAIL_ALREADY_TAKEN :: 126801",
    "type": "error",
    "code": "126801",
    "reason": null,
    "details": null,
    "timestamp": "2026-09-21T12:34:56.789Z"
  }
}
```

> Формат поля `data` при ошибке — это **сам объект ошибки**, без дополнительной обёртки.
> `message` всегда имеет вид `"<КОД_СТРОКА> :: <числовой код>"`.

Ошибка протокола (например, событие без зарегистрированного обработчика):

```json
{
  "type": "callback",
  "callbackId": "любая-строка",
  "error": "<текст ошибки>",
  "data": null
}
```

### Сервер → клиент: push (уведомление)

```json
{
  "type": "event",
  "event": "[domain]: action",
  "data": { ... },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

Push-кадры не имеют `callbackId` и не требуют ответа.

## Комнаты (топики)

Push события доставляются в комнаты, на которые подписано соединение:

| Комната | Содержимое |
| --- | --- |
| `user::<user_id>` | Личные события (новые диалоги, избранное, статусы онлайн и т.п.). |
| `channel::<channel_id>` | События в каналах/группах: сообщения, участники, темы. |
| `bot::<bot_id>` | События ботов. |
| `broadcast::<cast_id>` | Обновления статуса трансляции (подписка через `[broadcast]: open`). |
| `cast_online_chat::<cast_id>` | Сообщения чата онлайн-трансляции. |
| `meet::<meet_id>` | События участников конференции (подписка через `[meet]: open`). |

Сервер сам подписывает соединение на `user::` и `channel::` при подключении; комнаты
`broadcast::` и `meet::` подписываются событиями `[broadcast]: open` / `[meet]: open`
и отписываются событиями `[broadcast]: close` / `[meet]: close`.

## Heartbeat (ping/pong)

Поддерживать соединение в живом состоянии можно событиями `[system]: ping`.
Отвечать сервер будет **только если в кадре указан `callbackId`**:

```json
{ "type": "event", "event": "[system]: ping", "callbackId": "1" }
```

Ответ приходит кадром callback:

```json
{ "type": "callback", "callbackId": "1", "error": null, "data": { "pong": 1726913696789 } }
```

`pong` — время на сервере в миллисекундах (Unix timestamp). Пинг без `callbackId`
ответа не получает.

## Отключение

- При разрыве соединения сервер обновляет время последней активности пользователя.
- Если у пользователя не осталось других активных соединений — собеседникам отправляется
  `[user]: online status` со `status: "offline"`.
- Приложение может сознательно закрывать сокет (например, событие `[session]: remove`
  закрывает соединение кодом **1008**).
