# HTTP: скачивание файлов

```http
GET /api/v1/storage/:document?token=<token>&size=...&rendition=...
```

- `:document` — id документа (UUIDv7).
- Токен доступа — через query-параметр `token` **или** заголовок
  `x-file-token: Bearer <token>`.
- Опциональные query-параметры:
  - `size` — ширина превью изображения из `metadata.thumbnails`
    (`400`/`800`/`1200`); сервер отдаёт `{папка}/<size>.webp`;
  - `rendition` — метка видео-рендерации из `metadata.renditions`
    (`360`/`720`/`1080`); сервер отдаёт `{папка}/q/<label>.mp4`.
    Неизвестная метка не ошибка: отдаётся оригинал.

## Ответ

- **302 Redirect** на временный presigned URL хранилища (клиент просто следует
  редиректу, чтобы получить файл).
- **401** — токен отсутствует (не передан ни query-параметром, ни заголовком).
- **403** — токен подделан/битый либо `document_id` в URL не совпадает с токеном.

## Примечания

- Токен — JWT типа `download-file`, короткоживущий (по умолчанию несколько минут).
- Если токен **протух** (но не подделан), сервер автоматически перевыпускает его
  и скачивание проходит — достаточно повторить запрос.
- Токенизированные файлы клиент получает в ответах API как объект
  [File](../objects/file.md).

## Загрузка файлов

Загрузка выполняется не через WebSocket, а прямым `POST` в хранилище по
presigned POST policy:

1. Клиент вызывает WS-событие подготовки (например, `[message]: get upload attach url`)
   и получает `{ targets, document_id }` — набор целей загрузки с полями
   подписанной политики.
2. Клиент отправляет `POST` на `target.url` мультипарт-формой: поля
   `target.fields` + файл под ключом `file`. Успех — `204 No Content`.
3. Полученный `document_id` используется в последующих API
   (`[message]: send` с `attachments`, `[user]: save avatar` и т.п.).

Полный сценарий — в [руководстве по файлам](../guides/upload.md).
