# server-to-client: комментарии

События раздела `[comment]`. Данные — объект [Comment](../../objects/comment.md).

Все события комментариев публикуются **в комнату `channel::<channel_id>`** того
канала, где лежит пост. `channel_id` резолвится по `comments.entity_id → messages.id →
messages.channel_id`, поэтому подписчик получает событие ровно тогда, когда у него
открыт соответствующий канал (или он в комнате сообщества).

> Комнаты `user::<user_id>` и `bot::<bot_id>` для комментариев **не** используются:
> ветка комментариев всегда принадлежит каналу, а не личному диалогу.

## `[comment]: new` — новый комментарий

```json
{
  "type": "event",
  "event": "[comment]: new",
  "data": { "…": "Comment (meta)" },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

`data` — объект [Comment](../../objects/comment.md) **без** `reactions`
(реакции клиент догоняет отдельным запросом, как и для сообщений).

Клиент использует событие, чтобы:

- добавить комментарий в открытую форму `Comments` (или в её очередь, если форма
  ещё открывается);
- увеличить счётчик комментариев под постом на 1 (в том числе когда форма закрыта).

Если форма комментариев открыта и комментарий догружается — клиент обязан
проверить, что событие новее его `last_comment_id`, иначе будет дубль.

## `[comment]: update` — изменение комментария

```json
{
  "type": "event",
  "event": "[comment]: update",
  "data": { "…": "Comment (meta)" },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

Событие приходит и при **серверном обновлении метадаты вложений** — например,
когда для видео созданы рендеринги (поле `renditions` заполняется после
отправки). Полный объект комментария заменяет прежнее состояние — обновите
локальное хранилище целиком.

## `[comment]: remove` — удаление комментария

```json
{
  "type": "event",
  "event": "[comment]: remove",
  "data": {
    "id": "UUIDv7",
    "channel_id": "UUIDv7",
    "entity_id": "UUIDv7",
    "entity_type": "message"
  },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

Текст удалённого комментария не присылается — клиент заменяет строку на
«Комментарий удалён».

Счётчик комментариев под постом уменьшается на 1.

## `[comment]: update post commenting` — комментарии под постом включены/выключены

```json
{
  "type": "event",
  "event": "[comment]: update post commenting",
  "data": {
    "channel_id": "UUIDv7",
    "message_id": "UUIDv7",
    "entity_id": "UUIDv7",
    "entity_type": "message",
    "is_commenting": false
  },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

Клиент обновляет поле `Message.is_commenting` у поста и состояние поля ввода
в форме `Comments`. Уже загруженные комментарии при этом **остаются на месте**:
закрытые комментарии по-прежнему читаются.

## Чего здесь нет

- **`[comment]: new reaction`** — push-уведомлений о новых реакциях нет.
  Клиент опрашивает реакции видимых комментариев по `[comment]: get reactions`
  (в сообщениях так же).
- **Событий изменения числа комментариев** — счётчик пересчитывается клиентом
  из `[comment]: new` / `[comment]: remove`, а при перезагрузке приходит
  готовым в `Message.count_comments`.
