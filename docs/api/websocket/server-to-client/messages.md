# server-to-client: сообщения

Изменения сообщений приходят **событиями ленты канала** `[channel]: feed`
(типы `message_new`, `message_edit`, `message_deleted`, `history_cleared`,
`messages_cleaned`) — единый формат для живой доставки и догонки, правила
применения и таблица типов — в разделе
[синхронизации канала](./channels.md#синхронизация-и-события-канала).

Формат события:

```json
{
  "type": "event",
  "event": "[channel]: feed",
  "data": {
    "channel_id": "UUIDv7",
    "type": "message_new",
    "pts": 123,
    "payload": { "message_id": "UUIDv7" }
  },
  "timestamp": "2026-09-21T12:34:56.789Z"
}
```

- `message_new` несёт только `message_id` — подгрузите сообщение отдельным
  запросом (`[message]: get data` либо порцией `[message]: get history`).
- `message_edit` несёт `message_id`; полный объект сообщения заменяет прежнее
  состояние — обновите локальное хранилище целиком. Событие приходит и при
  **серверном обновлении метадаты вложений** — например, когда для видео
  созданы рендеринги (поле `renditions` заполняется после отправки).
- `message_deleted` несёт массив `message_ids` — удалите все перечисленные
  сообщения.
- Доставка — в комнату `channel::<channel_id>` (см.
  [доставку](./README.md#доставка)); события ботов на их соединение
  `/api/v1/wss/bot` описаны в [bots-to-server](../bots-to-server/messages.md).

## Чего здесь нет

- **`[message]: new reaction`** — push-уведомлений о новых реакциях нет.
  Клиент опрашивает реакции по `[message]: get reactions`
  (в комментариях — так же, см. [comments.md](./comments.md)).
- **Входящих реакций ботам** — бот получает реакции только по своему
  опросу; рассылка событий о реакциях в топик `bot::<bot_id>` не выполняется.
