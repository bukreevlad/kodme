# calls — звонки (LiveKit)

События раздела `[call]`. Звонки «один-на-один» и **групповые**: медиапотоки
идут через LiveKit, сигналинг (вызов, принятие, участники) — через WebSocket.
Участник получает **токен доступа к комнате звонка** и подключается к ней
LiveKit-клиентом (эндпоинт и обмен медиа — см. [гайд WebRTC / LiveKit](../../guides/webrtc.md)).

Звонок идёт в контексте личного диалога: при создании и завершении в диалог
пишутся системные сообщения (о входящем звонке, пропущенном, завершённом).

Приватность: доступ определяется настройкой `privacy_calls` вызываемого
пользователя (`"all"` — всем, `"contacts"` — только контактам; иначе
`ACCESS_DENIED_CALLS_RESTRICTED`). Если пользователь не найден —
`ACCESS_DENIED_USER_NOT_FOUND`.

## `[call]: start` — позвонить пользователю

```json
{ "user_id": "UUIDv7" }
```

`user_id` — кого вызываем. Имя и аватар звонящего сервер берёт из его сессии.

Ответ:

```json
{ "call_id": "UUIDv7", "token": "…", "is_merged": false }
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `call_id` | `string` | Id звонка. |
| `token` | `string` | Токен доступа к комнате звонка (LiveKit) для звонящего. |
| `is_merged` | `boolean` | `true` — звонящий влился в уже идущий звонок собеседника (групповой); `false` — создан новый звонок. |

Вызываемому (на все его соединения) приходит push
[`[call]: incoming`](../server-to-client/calls.md) и push-уведомление на
устройства.

Групповые звонки:

- если у собеседника уже идёт **принятый** звонок — инициатор вливается в него
  (`is_merged: true`); собеседнику входящий звонок не дублируется — нового
  участника он видит по событиям LiveKit-комнаты;
- нового участника в существующий звонок добавляет `[call]: add participant`.

Ошибки: `CALL_BUSY` (инициатор уже в звонке, либо звонок собеседника ещё не
принят), `DIALOG_NOT_FOUND`, `ACCESS_DENIED_*` (см. приватность выше).

## `[call]: accept` — принять звонок

```json
{ "call_id": "UUIDv7" }
```

Ответ:

```json
{ "call_id": "UUIDv7", "token": "…" }
```

`token` — доступ к комнате звонка для принявшего. Push-уведомления о звонке
на других устройствах принявшего снимаются. Если принявшего не было в списке
участников звонка — ошибка `NOT_INVITED`.

## `[call]: decline` — отклонить звонок

```json
{ "call_id": "UUIDv7", "reason": "declined" }
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `reason` | `string` | `"declined"` (нажал «Отклонить») \| `"timeout"` (никто не ответил за таймер звонка). |

Ответ — пустой. Повторное отклонение безопасно (участник уже вышел).
Если после отказа участников в звонке не осталось — инициатору приходит push
[`[call]: declined`](../server-to-client/calls.md), и звонок завершается.

## `[call]: leave` — выйти из звонка

```json
{ "call_id": "UUIDv7" }
```

Ответ — пустой. Остальные участники видят выход по событиям LiveKit-комнаты.
Если вышел **инициатор при ещё не принятом звонке** — звонок отменяется
целиком: приглашённым уходит `[call]: declined` (`reason: "cancelled"`).
Когда в звонке не остаётся участников — он завершается.

## `[call]: add participant` — добавить участника (групповой звонок)

```json
{ "call_id": "UUIDv7", "user_id": "UUIDv7" }
```

`user_id` — кого добавляем. Ответ — пустой. Приглашённому приходит push
[`[call]: incoming`](../server-to-client/calls.md) и push-уведомление; он
подключается через `[call]: accept`.

Ошибки: `CALL_NOT_ACTIVE` (звонок уже завершён), `NOT_A_MEMBER`
(приглашает не участник звонка), `ALREADY_PARTICIPANT` (приглашаемый уже
в звонке), `IDS_CANNOT_MATCH` (нельзя пригласить самого себя).
