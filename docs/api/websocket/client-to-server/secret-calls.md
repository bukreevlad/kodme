# secret-calls — секретные звонки (WebRTC P2P)

События раздела `[secret-call]`. Секретный звонок «один-на-один» поверх
прямого WebRTC-соединения устройств с медиа (аудио/видео шифруются
**DTLS-SRTP** — стандартным шифрованием WebRTC). Сервер участвует только в
**сигналинге** (обмен SDP/ICE): медиапотоки идут между устройствами напрямую
(или через TURN-ретрансляцию — уже зашифрованными).

Секретные звонки **не связаны с секретными чатами** — у них свой раздел
событий и свой идентификатор разговора `call_id` (UUIDv7, генерирует
звонящий).

Как и секретные чаты, звонки живут на парах устройств:

- сигналы адресуются устройству (`target_device_id` = session_id);
- список онлайн-устройств собеседника получите подпиской на присутствие —
  см. [`secret-chats.md`](./secret-chats.md) (`[secret-chat]: presence subscribe`);
- **вызов рассылается на все онлайн-устройства собеседника**: каждое показывает
  экран входящего звонка, соединение устанавливается с тем устройством,
  которое ответило `answer`; остальным можно разослать `hangup`.

ICE-серверы для WebRTC выдаются сервером в ответе HTTP `POST /api/v1/auth/check`
(поле `server_data.web_rtc.ice_servers`).

## `[secret-call]: signal` — WebRTC-сигнал звонка (SDP/ICE)

```json
{
  "call_id": "UUIDv7",
  "target_device_id": "UUIDv7",
  "type": "offer",
  "sdp": "v=0…",
  "candidate": null
}
```

| Поле | Тип | Описание |
| --- | --- | --- |
| `call_id` | `string` | Id звонка (UUIDv7, генерирует звонящий). |
| `target_device_id` | `string` | Устройство-получатель (session_id). |
| `type` | `string` | `"offer"` \| `"answer"` \| `"candidate"` \| `"hangup"`. |
| `sdp` | `string \| null` | SDP (для `offer`/`answer`). |
| `candidate` | `string \| null` | ICE-кандидат, JSON-строка (для `candidate`). |

Ответ — `{ "delivered": true }`. Устройству-получателю приходит push
[`[secret-call]: signal`](../server-to-client/secret-calls.md). Если устройство
собеседника пропало из сети — ошибка `PEER_OFFLINE`.

Типичный сценарий:

1. Звонящий генерирует `call_id`, создаёт соединение с медиа-дорожками и
   шлёт `offer` **всем** онлайн-устройствам собеседника.
2. Устройство, на котором приняли звонок, отвечает `answer` (на `from_device_id`
   звонящего) и шлёт свои `candidate`; звонящий — свои `candidate`.
3. Отказ/завершение/отмена — `hangup` (принявшим устройствам звонящего,
   либо звонящему с отказавших устройств).
